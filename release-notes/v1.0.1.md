# StreamParser v1.0.1

补丁版本。**建议 1.0.0 的用户升级**：本版修掉了四个会导致进程挂死或功能静默失效的缺陷，
其中两个在 1.0.0 里就能稳定复现。

公开 API 没有变化，下游不需要改代码，重新 `find_package(sp 1.0)` 即可。

## 修复

### 串口设备缺失时 `start()` 挂死

`device` 为空时 `TransportBase::start()` 会从 io 线程回调 `stop()`，而 `stop()` 要 join
那个线程——自己 join 自己，进程直接卡住。示例程序里一条命令就能复现：

```bash
./TransportDemo serial ""
```

改为在 io 线程上只做关闭，join 留给调用线程。

### TCP 客户端断线后 `stop()` 挂死

`stop()` 原来先释放 work guard 再投递关闭任务。当 io 线程已经没有别的事可做时，
`io_context::run()` 在 guard 释放的瞬间就返回了，关闭任务投递进去却永远不会被取走，
`future.wait()` 一直等到进程结束。

触发路径很平常：让 `tcp_client` 连上一个服务端，断掉它（或等 `link_idle_timeout_ms`
生效），再调 `stop()`。改为先投递、再释放 guard。

### UDP 随机端口的 tag 报错

`port = 0` 让内核分配端口时，`local_tag_` 在构造阶段就按 `config().port` 拼好了，
那时还是 0。于是 `on_link_up` 告诉宿主「我在 `udp:0`」，宿主按这个 tag 回包必然失败。
现在在 bind 成功后按实际端口重算。

### UDP 主机名解析取到 IPv6 地址

解析结果直接取第一条。`localhost` 在多数系统上优先解析到 `::1`，而 socket 是 IPv4——
发送无声失败，没有任何回调。现在取第一个 IPv4 结果，一个都没有时报 `-7`。

### `links()` 里查不到 UDP 的 socket 自身

`on_link_up` 会报出 `udp:<port>`，但那个 tag 从未进入链接表，`links()` 里永远找不到它。
现在它作为「可上报但不可发送」的链接注册：`links()` 与 `on_link_up` 返回同一份内容，
`send()` 到它返回 `false`，`broadcast()` 跳过它，两者都不会产生错误回调。

### keepalive 配置失败时静默

两个适配器的 `enable_keepalive()` 把 `setsockopt`（Linux）和 `WSAIoctl`（Windows）的
返回值全部丢弃。参数被系统拒绝时配置静默失效——宿主以为探测开着，实际只能等下一次
写失败才发现对端已经消失。

现在每个选项的失败都记一条 WARN，带上选项名、期望值和错误；`SO_KEEPALIVE` 改用不抛
异常的 `set_option` 形式，失败只记日志，不再把 `std::system_error` 抛进连接建立流程。
设置失败不会让连接失败——keepalive 是优化，不是前置条件。

## 测试

这一版的修复全部来自新增的可靠性测试，它们把门面本身当作被测对象，
在进程内用裸 asio socket 充当对端：

- `transport_facade`（194 项断言）：TCP 服务端/客户端的粘包拆包、帧超时、校验失败、
  tag 路由、`broadcast()`、发送预算（`-2`）、`max_links`（`-6`）、写失败只报一次、
  `start()` 失败（`-5`）、重连与空闲超时；UDP 的多 peer 路由、`send_to()`、
  `peer_host`/`peer_port` 固定目标
- `transport_serial`（26 项）：设备缺失与未配置路径在任何平台都跑；真实收发需要
  一对串口，由 `SP_TEST_SERIAL_PORT` / `SP_TEST_SERIAL_PORT_PEER` 启用
- `transport_keepalive`（35 项）：keepalive 的四个参数从内核读回比对，非法值被拒时
  产生 WARN 且不影响其余选项；`log_link_events` 开关对连接/断开日志的实际控制

已验证 Windows x64（MSVC `/W4`）、Linux x64 与 armv7 Hi3516 交叉编译，
三处均零警告、全部通过。串口真实收发在物理 COM 口与板载 `/dev/ttyAMA` 上都跑过。

## 交叉编译

新增 `cmake/hi3516-toolchain.cmake`，面向海思 `arm-himix200-linux` 工具链
（GCC 6.3、Cortex-A7、glibc）：

```bash
cmake -S . -B build-arm -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_TOOLCHAIN_FILE=cmake/hi3516-toolchain.cmake
cmake --build build-arm -j
```

工具链装在别处时加 `-DHI3516_TOOLCHAIN_DIR=/path/to/arm-himix200-linux`。

## 兼容性

- C++14 编译器：GCC 5+ / Clang 3.4+ / MSVC 2015+
- 公开头文件、`sp::core` / `sp::transport` 目标名、`find_package(sp 1.0)` 均未变化
- keepalive 被拒时由“静默”变为“记一条 WARN”：日志级别为 `warn`，
  宿主若把 `splog::Level` 设为 `error` 及以上则不可见

完整变更见 [CHANGELOG.md](https://github.com/leiddev/StreamParser/blob/master/CHANGELOG.md)。
